# 构建与发布及闪退排查指南

## 构建与发布

- 每次改版必须使用带时间戳的 `versionName`，并同步更新单调递增的 `versionCode`。
- 发布必须依次完成：删除手机上的旧版应用、安装新版 APK、核对手机上实际安装的版本号；三个步骤缺一不可。

### 装机一律走脚本，别手动"卸载 + 安装"

`android/install-apk.ps1` 就是为此写的：备份数据 → 卸载 → 装新版 → 还原数据 → **按新 uid 校正文件归属** → 恢复无障碍和悬浮窗权限 → 自检。

```powershell
pwsh -File android/install-apk.ps1 -Apk "F:/Aaiagent/ceshibao/AI托管助手-vX.apk"
```

2026-10-06 晚上手动装了一次，跳过了这一步，App 起来就闪退（排查过程见下节）。

### 万一手动装出闪退：数据目录属主不符

安卓在重装应用后可能分配一个**新的 uid**，但旧的数据目录不一定被清掉。这时新 App 读不了旧 uid 的文件，**一启动就闪退**，报错形如：

```
android.database.sqlite.SQLiteCantOpenDatabaseException:
Cannot open database '/data/user/0/com.aaiagent/databases/aaiagent.db':
File /data/user/0/com.aaiagent/databases/aaiagent.db is not readable
```

原因：数据文件权限是 `-rw-rw----`，只有属主和同组能读。新 App 换了 uid，既不是属主也不在组里，所以"不可读"。

**第一步，查两个 uid，对不上就是这个问题：**

```powershell
adb shell "dumpsys package com.aaiagent | grep userId"
adb shell "su -c 'ls -la /data/data/com.aaiagent/databases/'"
```

**第二步，把数据目录改归当前 uid**（把下面的 `10557` 换成第一步查出来的数字）：

```powershell
adb shell "su -c 'chown -R 10557:10557 /data/data/com.aaiagent'"
```

改完直接启动 App 即可，**数据不会丢**（设备密钥、配置、托管开关都还在）。这条修复只动手机上的文件属主，不改代码、不需要提交。

**预防：卸载旧版后，先确认数据目录真的没了，再装新版：**

```powershell
adb shell "su -c 'ls /data/data/com.aaiagent'"
```

报"没有那个文件或目录"才装新版。
