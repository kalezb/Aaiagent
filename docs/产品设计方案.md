# 产品设计方案

> v1.0 | 2026-09-23

---

## 一、产品定位

### 一句话

**一台手机同时托管多个社交平台的聊天，AI替你回复，你能随时插手。**

### 目标用户

在 Soul、QQ、陌陌、连信等平台上需要高频聊天，但时间不够用的人。典型场景：

- 做社交电商的，一个人要维护几十个联系人
- 同时玩多个社交 App，切来切去太麻烦
- 不想冷落任何人，但精力实在有限

### 用户痛点

| 痛点 | 产品怎么解决 |
|------|------------|
| 多个 App 之间来回切换 | 一个 App 同时监控四个平台 |
| 消息太多回不过来 | AI 自动生成回复并发送 |
| 担心 AI 说错话 | 随时人工接管，或者只让 AI 写草稿 |
| 换平台后 AI 不记得聊过什么 | 跨平台共享记忆，云端存聊天历史 |
| 不会调 AI 人设 | 内置"阿杰""小夏"两套人设，一键切换 |

## 二、功能全景

### 2.1 核心功能

**AI 聊天托管（Hero Feature）**

打开开关 → App 自动监控四个平台的消息 → 发现未读消息 → 读内容 → 调 AI 生成回复 → 自动发出去 → 继续巡逻。

整个过程不需要用户碰手机。

**四种工作模式**

| 模式 | AI 做什么 | 用户做什么 |
|------|----------|-----------|
| **全自动** | 读消息 → 生成回复 → 自动发送 | 什么都不用做 |
| **写入门禁** | 读消息 → 生成回复 → 粘贴到输入框 | 审核后手动点发送 |
| **监控模式** | 读消息 → 存云端（不回复） | 自己手动回复 |
| **关闭** | 什么也不做 | 正常使用手机 |

**人工接管**

任何时候用户碰屏幕、点悬浮窗、或者在通知栏关掉开关，AI 立即停手，不等当前操作完成。

### 2.2 多平台适配

| 平台 | 适配难点 | 解决方案 |
|------|---------|---------|
| Soul | 界面简洁 | View ID 定位，最稳定 |
| QQ | v8/v9 版本界面差异大 | 自动检测版本，走不同适配器 |
| 陌陌 | UI 结构深 | 启发式节点搜索 |
| 连信 | 有多个包名 | 双包名兼容 |

加新平台只需写一个「适配器」——6 个标准方法，不需要改核心引擎。

### 2.3 人设系统

**内置两套人设：**

- **阿杰**（男）：30 岁，餐馆老板。接地气、会聊天、偶尔自嘲。说话带点方言味，不装。
- **小夏**（女）：28 岁，公司白领。温柔但不做作，有主见，偶尔有点小幽默。

**交互规则：**

- 一个人设通用于所有平台——在 Soul 上是阿杰，在 QQ 上还是阿杰
- 切换人设后，所有平台立即生效
- 后续可扩展自定义人设：用户自己写一段描述，AI 自动扩展成 system prompt

### 2.4 跨平台记忆

QQ 上跟某人聊过的事情，换到 Soul 上再遇到同一个人（基于昵称+平台匹配），AI 还能记得。

实现方式是所有聊天记录存云端数据库，调用 AI 时自动带上历史。

隐私考虑：用户可以一键清除某个联系人的所有记录。

### 2.5 Dashboard 管理面板

一个网页后台，方便用户在电脑上管理：

- 📊 看统计：今天回了多少条消息、活跃联系人排行
- 📝 查记录：按平台和联系人筛选聊天记录
- 👤 管人设：修改人设描述、切换当前人设
- 📇 管白名单：哪些联系人允许 AI 回复
- 🤖 换模型：改 API Key、换模型，不用动代码

### 2.6 安全机制

| 场景 | 保护措施 |
|------|---------|
| AI 连续回复同一条消息 | 消息去重：同一消息 ID 5 分钟内不重复处理 |
| AI 给陌生人回复 | 联系人白名单：只回复指定的人 |
| 对方发来敏感内容（借钱、账号密码） | 检测到敏感词 → 自动回安全话术 → 通知用户 |
| 平台弹违规/封号警告 | 自动检测弹窗 → 关闭弹窗 → 暂停该平台托管 |
| 操作卡住 | 150 秒超时 → 放弃本次 → 记录日志 → 继续巡逻 |
| 多个手机同时在线同一账号 | 后端检测 → 选一台做主设备 → 其他暂停并通知用户 |

## 三、使用流程

### 3.1 首次使用

`
安装 App → 授权无障碍服务 → 授权通知监听 → 选择平台 →
选择人设 → 设置白名单 → 打开托管开关 → 搞定
`

全程引导式，每一步都有说明，不需要用户自己摸索。

### 3.2 日常使用

每天就两个操作：

- **打开悬浮窗开关** → AI 开始工作
- **关闭悬浮窗开关** → AI 停手

不需要频繁打开 App。悬浮窗是一个绿色小圆点，贴在屏幕边缘，不碍事。

### 3.3 用户介入场景

- **想自己回某句话**：手指碰屏幕，AI 感知到立即让路
- **想看一下 AI 回了什么**：打开 Dashboard，按联系人筛选查看
- **不想 AI 回某个人了**：Dashboard 里从白名单移除
- **AI 回复风格不满意**：Dashboard 换个人设或者改描述

## 四、核心交互

### 4.1 悬浮窗

屏幕右边缘中间一个绿色小点（约 8dp 大小）：

| 操作 | 效果 |
|------|------|
| 单击 | 开/关托管（有触觉反馈 + 短震动） |
| 长按 | 打开 App 主界面 |
| 拖动 | 沿屏幕边缘上下移动，松手吸附到最近边缘 |

颜色状态：
- **绿色** = 托管中
- **灰色** = 已暂停
- **红色闪烁** = 异常（比如某个平台需要重新登录）

### 4.2 通知栏

一条常驻通知：

- 显示当前托管状态（"托管中 · 3个平台"）
- 快捷按钮：暂停 / 恢复
- 展开显示最近一条 AI 回复的摘要

### 4.3 App 主界面

简洁为主，就三个 Tab：

| Tab | 内容 |
|-----|------|
| 控制台 | 托管开关、当前状态、平台连接状态 |
| 记录 | 今日回复数、最近聊天预览 |
| 设置 | 人设选择、白名单管理、平台开关 |

## 五、隐私与安全

### 用户承诺

- 聊天记录默认加密存储
- 用户可以随时删除任意联系人的全部记录
- 不上传通讯录、不读相册、不碰短信
- App 只在执行托管时读取聊天内容，其他时间不监控屏幕

### 技术保障

- 数据传输全程 HTTPS 加密
- API 请求需要 Token 鉴权
- 数据库中的消息内容应用层加密（即使数据库泄露也读不了）
- 用户删除的数据 24 小时内物理清除

## 六、成功指标

### 用户侧

| 指标 | 目标 |
|------|------|
| 从安装到首次托管完成 | < 5 分钟 |
| AI 回复质量（用户不用手动改） | > 80% |
| App 崩溃率 | < 0.5% |
| 杀后台后恢复成功率 | > 95% |

### 产品侧

| 指标 | 说明 |
|------|------|
| 日活托管时长 | 平均每天托管多少小时 |
| 平台覆盖数 | 平均每人用几个平台 |
| 回复量 | 日均 AI 代回复条数 |
| 人工介入频率 | 越低说明 AI 越靠谱 |

## 七、不做的事情（防止跑偏）

- ❌ 不做 iOS 版（先聚焦 Android）
- ❌ 不做内置聊天（我们是托管工具，不是聊天 App）
- ❌ 不做免费版 + 付费版分层（先做一个版本验证）
- ❌ 不做语音/视频通话处理（只处理文字消息）
- ❌ 不做自定义插件市场（等核心功能稳定后再说）
- ❌ 不做自研大模型（用现成的 API）
