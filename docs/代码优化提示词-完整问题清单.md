## 一、核心问题清单（按优先级排序）

### P0 - 最严重，不改不能用

#### 问题1：没有空闲保护，跟用户抢控制权
**现状**：轮询每2秒跑一次，不管用户在屏幕上干嘛都继续执行，会把用户手动点进去的聊天页拉回消息列表。
**改成**：
- 在GestureMonitor里记录用户最后一次触摸时间
- 轮询循环开头先检查：如果用户最近5秒内碰过屏幕，直接跳过这轮，等下一轮
- 这个判断要加在 `startHosting` 的 while 循环最开头
- 用户停手5秒后才继续自动化操作

#### 问题2：进聊天页后不验证标题，进错人不知道
**现状**：点了会话进去后，只检查"是不是聊天页"就开始读消息，可能进错了人。
**改成**：
- 进聊天页后等2.5秒
- 读顶部标题栏文字（Soul的ID是 `tv_title`）
- 对比这个标题是不是你要点的那个联系人名字
- 如果标题对不上，按返回键退回消息列表，放弃这个会话，继续找下一个未读
- 如果对上了，才继续读消息

#### 问题3：Soul的isInChat要求太严格
**现状**：要求同时有 `et_sendmessage` 和 `item_root` 两个ID才算聊天页，Soul加载慢的时候item_root还没出来，就判断不在聊天页。
**改成**：
- 改成：有 `et_sendmessage` 就算聊天页，不要求同时有 `item_root`
- 等加载完了item_root自然会出现

---

### P1 - 影响稳定性

#### 问题4：滑动后不验证列表稳定
**现状**：滑动后等800ms就读，列表还在动画，读到过渡状态。
**改成**：
- 滑动后等1秒
- 连续读两次列表内容（会话数量+第一个会话名），间隔500ms
- 两次一样才算稳定，不一样就再等1秒再读，最多等3次

#### 问题5：点会话后等待时间太短
**现状**：点完会话等1秒就开始检查，Soul加载慢，1秒还没进去。
**改成**：
- 点完会话后等2.5秒
- 然后开始检查是不是聊天页
- 不是的话再等1秒检查一次，最多等5次（总共7.5秒）

#### 问题6：发送按钮查找没有重试
**现状**：找发送按钮只找一次，找不到就放弃。
**改成**：
- 输入文字后等1秒让发送按钮出现
- 找发送按钮，找不到等500ms再找，最多找5次
- 5次都找不到，用坐标兜底（输入框右边中间位置）
- 点完发送后等800ms，检查输入框是不是空了，确认发出去了

#### 问题7：违规弹窗关键词太少
**现状**：只检测4个关键词，很多弹窗认不出来。
**改成**：把检测关键词扩充成：
```
发送失败、已被禁言、发言太快、内容违规、违规消息、账号异常、操作频繁、
请稍后再试、已被限制、禁止发言、聊天功能被封、举报处理中、
违反社区规定、请遵守、发送内容包含、封号、永久封禁、临时封禁
```

### P2 - 影响体验

#### 问题8：轮询间隔太短
**现状**：每2秒轮询一次，太频繁。
**改成**：改成3秒，减少跟用户抢的概率。

#### 问题9：弹窗关闭逻辑太简单
**现状**：只找"关闭/取消/X"按钮，很多弹窗认不出来。
**改成**：
- 弹窗关键词扩充：允许、取消、确定、关闭、知道了、好的、不再提示、关闭广告
- 找不到关闭按钮就按返回键
- 连续按2次返回键关掉弹窗

#### 问题10：错误恢复重试次数太少
**现状**：只重试2次就放弃。
**改成**：重试3次，每次间隔1秒。
