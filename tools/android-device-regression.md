# 安卓真机回归检查

这份检查只负责确认软件没有明显炸掉，不会自动开启托管，也不会自动发消息。

## 自动冒烟检查

先确认手机已经连接，并且开发者调试已经打开。

只检查当前安装包：

```powershell
powershell -ExecutionPolicy Bypass -File tools/android-device-smoke.ps1
```

先重新安装最新安装包，再检查：

```powershell
powershell -ExecutionPolicy Bypass -File tools/android-device-smoke.ps1 -Install
```

脚本会做这些事：

1. 打开 AI 托管助手。
2. 确认确实进入了客户看板页面。
3. 保存一张手机截图和一份界面记录。
4. 检查通过就输出“Device smoke check passed”。

截图和界面记录默认放在 `Alinshi/android-device-smoke`。

## 必须人工检查的流程

自动检查不能代替真实聊天。每次改动托管、发送、页面识别、照片或语音后，按下面顺序查一遍。

1. 先关托管，确认软件不会自己回消息。
2. 开启托管，找一个测试联系人发一条普通消息，确认只回一次。
3. 同一条消息重复发两遍，确认不会回两遍。
4. 对方连续发多句话，确认按一批理解，不会把每句当新客户。
5. AI 正在处理时手动摸屏幕，确认它会停下，不跟人抢操作。
6. 切到另一个联系人，确认不会把上一个人的话发错人。
7. 后台改一条规则，保存后下一条消息马上按新规则回。
8. 后台删一条规则，保存后下一条消息不再出现那套说法。
9. 让对方要照片，确认只发允许的图片，不发错组，也不重复发。
10. 发一条有文字的语音和一条没转文字的语音，确认两种处理不同，不会假装听懂。
11. 发送过程中把网络关掉再打开，确认不会重复发送，恢复后能继续。
12. 重启手机，确认托管状态和待确认消息不会乱掉。

只要其中一项不符合，就停止继续改代码，先保留截图、界面记录和后台故障记录。
